# Project Phase 2: mC Parser and AST

**CS 4318, Compiler Construction**

## Overview

Build a parser for the **mC** language (a C-like language) that:

1. Consumes the token stream from the Phase 1 lexical analyzer (`scanner.l`)
2. Detects and reports **syntax errors** with line numbers
3. Constructs an **Abstract Syntax Tree (AST)** for valid programs
4. Builds a **symbol table** tracking each identifier's name, type, and scope

## Repository Structure

```
├── src/
│   ├── scanner.l      # Lexer (reuse from Phase 1)
│   ├── parser.y       # YACC grammar: implement rules and AST here
│   ├── tree.c / .h    # AST node definitions and printAst()
│   ├── strtab.c / .h  # Symbol table: djb2 hash, ST_insert, ST_lookup
│   └── driver.c       # Entry point, calls printAst() and prints the symbol
│                       #   table; provided, do not modify
├── test/
│   ├── cases/         # Sample .mC input programs
│   └── exp/           # Expected output for each test case
└── Makefile
```

> **Note:** Token definitions previously in `tokendef.h` are now generated by `parser.y`. Do not use a separate `tokendef.h`.

## Building

```sh
make clean && make
```

The binary is written to `obj/mcc`.

## Running

The compiler accepts input in four ways:

```sh
./obj/mcc input.mC              # file argument
./obj/mcc < input.mC            # file redirect
cat input.mC | ./obj/mcc        # pipe
./obj/mcc                       # interactive (Ctrl-D to end)
```

## Testing

```sh
make test          # all 12 sample cases
make test ARGS=-v  # ...and print the full diff for anything that fails
```

This runs every case in `test/cases/` against the expected output in
`test/exp/`. Two things are deliberately **not** required to match, because the
assignment says so:

- **Symbol table indices.** They depend on your hashing and probing strategy.
  Entries are compared as a set and the numbers on the left are ignored.
- **Pass-through AST nodes.** A node for a chain production
  (`expression` &rarr; `addExpr` &rarr; `term` &rarr; `factor`, and
  `statement`, `decl`, `assignStmt`) that ends up with exactly one child is
  collapsed into that child before comparing, on both sides. Nested list nodes
  (`declList`, `statementList`, `argList`, `formalDeclList`) are flattened.

So `make test` can say `PASS*` while plain `diff` against the `.exp` file still
shows differences. That is expected, and it is the same comparison used for
grading.

The five programs in `test/errors/` are not scored by `make test`; run them by
hand to check your error handling:

```sh
./obj/mcc test/errors/errSyntax.mC       # expect: error, with a line number
./obj/mcc test/errors/errUndeclared.mC   # expect: a warning naming j
./obj/mcc test/errors/errLeadZero.mC     # expect: error, line AND column
./obj/mcc test/errors/errIdNum.mC        # expect: error, line AND column
./obj/mcc test/errors/errComment.mC      # expect: error, line AND column
```

## What to Implement

### `parser.y`
- Express the mC grammar as YACC rules
- Resolve any shift/reduce or reduce/reduce conflicts without changing grammar semantics
- Call `ST_insert` on every declaration (`varDecl`, `formalDecl`, `funDecl`)
- Call `ST_lookup` on every use (`var`, `funCallExpr`) and emit an undeclared-symbol warning if not found
- Build and connect AST nodes using `maketree` / `maketreeWithVal` / `addChild`

### `tree.c`
- Implement `maketree(kind)`, which allocates a node with zero children
- Implement `maketreeWithVal(kind, val)`, which allocates a leaf node storing a value
- Implement `addChild(parent, child)`, which wires a child into the parent node
- Implement `printAst(root, nestLevel)`, which recursively prints the AST, indented by 2 spaces per level; include extra info for identifiers, integer/char/string constants, operators, and type specifiers (see expected output files for exact format)

### `strtab.c`
- Implement `ST_insert(id, scope, data_type, symbol_type)`; hash key = djb2(`scope` + `id`) % `MAXIDS`
- Implement `ST_lookup(id, scope)`; search by the same key, returning the index or -1 if not found
- Symbol table entry fields: `id`, `scope` (function name or blank for globals), `data_type` (`INT_TYPE`, `CHAR_TYPE`, `VOID_TYPE`), `symbol_type` (`SCALAR`, `ARRAY`, `FUNCTION`)

## AST Output Format

Each node prints on its own line. Children are indented +2 spaces relative to their parent. Nodes carrying extra information use a comma-separated suffix:

```
program
  declList
    decl
      funDecl
        funcTypeName
          typeSpecifier,void
          identifier,main
        funBody
          ...
            addop,+
            integer,3
```

The symbol table prints after the AST:

```
SYMBOL TABLE:
91: int main:i
242: void :main()
```

Hash indices will vary with your implementation, and that is expected per the
assignment. Do not try to reproduce the exact numbers in `test/exp/`: those were
generated by an implementation that hashes the identifier alone, whereas section
5 of the handout asks you to hash the scope concatenated with the identifier.
Either is accepted. What is checked is the set of entries, not the indices.

## Error Handling

| Error | Behavior |
|---|---|
| Syntax error | Print line number where the program deviates from the grammar |
| Undeclared symbol | Print a warning (not a hard error at this phase) |
| Scanner errors (unterminated comment/string, bad escape, leading-zero int, id starting with digit) | Report line + column number |
